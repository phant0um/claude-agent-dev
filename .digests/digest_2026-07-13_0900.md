## Themes

### 1. Cost-Aware Orchestration via Model Routing
We have fundamentally shifted the core execution logic to manage model costs dynamically using a tiered approach. Instead of defaulting to expensive models, the system is designed around the principle: **Premium Orquestrates / Cheap Executes.**
*   **Mechanism:** The `model-router` now uses capability profiles (`deterministic`, `economy`, `standard`, `deep`, `critical`) to map tasks to specific model tiers (Haiku, Sonnet, Opus).
*   **Intent:** To ensure that expensive models (like Opus) are only consulted for critical decision points or complex diagnostics where capacity is paramount. For routine work and volume (e.g., classification, formatting), cheaper models handle the bulk of the workload, significantly optimizing token expenditure while maintaining high capability where needed.

### 2. Agent Memory & State Persistence (`Ledger`)
The memory system has evolved from simple log appending to a state management system focused on *what* was learned, not *what* was said.
*   **Mechanism:** The Ledger now manages memory based on **Salience** (how often an entry is re-referenced/citated) and **Decay** (lifetime of user/session/agent). Decay moves entries to archived logs rather than deleting them, ensuring history is recoverable.
*   **Intent:** To manage cognitive load efficiently. Agents only retain highly salient information and principles that have survived decay, discarding transient conversational noise to maintain a focused operational memory.

### 3. Fullstack Specialist Team & Workflow (`Fullstack Agent System`)
A new systemic shift defines complex development tasks as coordinated efforts by specialized senior engineers. This system enforces disciplined, evidence-based workflows.
*   **Mechanism:** The orchestrator (`Maestro`) delegates tightly defined sub-tasks to specialist agents (Stratum for Backend, Facet for Frontend, Bastion for Infra, etc.). All deliverables require **Evidence** and pass through mandatory security checks (`Sentinel`).
*   **Intent:** To leverage domain expertise efficiently. By forcing required evidence and structured delegation, the system demands testable code and robust infrastructure configurations, treating agents as senior professionals rather than simple tutors.

### 4. High-Rigor Quality Gates (`Forge` & `Neuron`)
Quality assurance has been formalized into strict, binary gate checks that prioritize structural integrity over superficial syntax.
*   **Mechanism:** The `forge` agent uses a **5E Rubric**, where findings are categorized as **Blocking** (critical defects in efficiency/effectiveness/security) or Non-blocking (style). The DB migration review combines 5E analysis with specific schema safety checks (locking, data loss).
*   **Intent:** To prevent cascading failure and technical debt. By enforcing blocking gates on structural defects (e.g., coupling, N+1 queries), the system ensures that code is not just *syntactically correct*, but truly robust and maintainable.

## Watch Out: Gotchas before deploying
*   **Model Tier Misuse:** The new capability profiles require careful task mapping. If you use a `critical` required step for routine work, it will fail dramatically (requiring manual review). Always verify the intent maps correctly to risk/capacity requirements.
*   **Evidence Mandatory:** Deliverables from systems like `fullstack-agent-system` are useless without accompanying Evidence (test outputs, logs, specs). Agents *refuse* tasks that lack evidence checkpoints.
*   **Forge Findings Are Blocking:** Pay attention to findings flagged as **Blocking**. These typically relate to structural errors (SRP violations, security breaches, critical query failures) and will halt the desired action unless explicitly overridden by a strong `REFACTOR` command.
*   **Database Migration Risk:** The new migration review is extremely strict about potential data loss, table locking, and rollback safety. A single poorly defined change can result in a **DANGEROUS** verdict, freezing deployment until compensatory measures are provided.
